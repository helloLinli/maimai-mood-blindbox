## 二、逐个情绪：怎么配、为什么这样配


### EO-00 说不清（`whatever`）

- **一句话诊断**：今天不想选，那就别选
- **气质**：交给我决定
- **优先标签**：`classic`、`comfort`
- **标签加分**：classic +1.2、comfort +0.8、premium +0.4
- **标签扣分**：—
- **辣度偏好**：不限
- **套餐骨架**（人数为 1 时）：主食 1 份、配餐 1 份、饮品 1 份、甜品可选
- **命名模板**：「交给这一盒 · {main}」 / 「不问为什么 · {main}」 / 「今天就听它的 · {main}」
- **推荐理由（小票上印的就是这三句之一）**：
  1. 说不清就可以不选。这一盒替你把决定做完，你只负责吃。
  2. 经典款是最不容易出错的答案，今天先要一个不出错的下午。
  3. 搭配里留了一点甜的，因为完全没惊喜的一餐也不好吃。
- **为什么这样配**：见下表营养目标与标签权重。该情绪把「classic + comfort」排在前面，是因为这一状态下人最需要的是立刻可感的身体反馈（热量、蛋白质、温度、口感），而不是需要阅读的说明。

## 三、出盒规则（可手算）

### 3.1 硬过滤（先淘汰，不参与打分）

1. **时段**：早餐时段（约 10:30 前）只用 `meal = breakfast` 或 `all` 的餐品；正餐时段只用 `meal = all`。
2. **忌口**：餐品的 `contains` 与用户忌口有交集 → 直接剔除。
3. **辣度**：`spicy > 用户辣度上限` → 剔除。
4. **情绪硬规则**：`hardRules.handheld = true` 的情绪（赶时间），所有餐品必须 `handheld = true`。
5. **预算**：组合总价 > 预算 → 淘汰。**人均热量上限**：人均热量超上限 → 淘汰。

### 3.2 剪枝（保证可计算）

- 每个品类先按「单件得分」降序排序，各取前 9/8/8/6 件进入组合枚举（主食/配餐/饮品/甜品）。
- 若枚举规模仍超过 8000 个组合（多人 + 庆祝时会出现），按「裁剪后能减少最多组合数」的品类，从它的末位开始删，直到回到上限内。剪枝只取决于数据本身，因此结果可复现。

### 3.3 打分公式

```text
单件得分 = Σ(标签加分) − Σ(标签扣分)
         + 0.9 × (命中的 dna 标签数)
         + （辣度 ≤ 情绪偏好 ? +0.4 : −0.5 × 超出级数）

整盒得分 = Σ(单件得分)
         + 0.8 × (整盒命中的 dna 标签数)
         + 2 × (1 − min(1, |人均热量 − 目标热量| ÷ 目标热量 ÷ 容差))
         + 1.6 × min(1, 人均蛋白 ÷ 目标蛋白)
         + 2.2 × (1 − |实付 ÷ 预算 − 预算使用比例| ÷ 0.5)
         + 结构修正：情绪要求甜品却没给 −1.5；非必需时给甜品 +0.2
```
（预算贴近度为负时按 0 计；实付 ÷ 预算 > 1 的组合已在硬过滤阶段淘汰。）

### 3.4 三盒产出

- **稳妥款（A）**：全场最高分。最贴着你的约束来的那一盒
- **惊喜款（B）**：换掉主食，且相对稳妥款至少换掉两个构成位（主食/配餐/饮品/甜品）。换掉了两个位置，但一样好吃
- **反套路款（C）**：主食、配餐、饮品三个位置全部换掉。三个位置全换，试一个没想到的

同分时按组合内餐品编码的字典序升序打破平局。若合法组合不足 3 个，允许重复结构，但必须保证 3 张可展示的盒子。

### 3.5 人数缩放

- 主食份数 = max(情绪骨架主食数, 人数)；饮品份数 = max(骨架饮品数, 人数)；配餐最多随人数放大到 2 份；甜品最多放大到 3 份。
- 热量与蛋白质目标按人数等比放大，预算按人数线性放大；组合总价仍受用户给出的**总预算**约束。
- **不浪费原则**：不主动把份数堆到吃不完；预算不足时优先减少配餐与甜品，并在小票上写明省掉了什么。

### 3.6 开盒与取餐码

```text
种子 = 日期 + 情绪 id + 预算 + 人数 + 辣度上限 + 忌口(排序) + 热量上限 + 时段 + 门店
开盒索引 = FNV1a32(种子 + "::reveal") mod 3
取餐码   = "#M" + (FNV1a32(种子 + "::pickup") mod 10000)
```
同一天、同一心情、同一约束 → 结果永远一致。改变任何一项输入，种子与结果都会变。

## 四、怎么加一个新情绪

1. 在 `engine/content.js` 的 `MOODS` 里增加一条：`id`（英文）、`code`（EO-xx）、`label`、`aliases`（用户可能说的话）、`vibe`、`diagnosis`、`dna`、`tagBoost`、`tagPenalty`、`spicyPref`、`kcalTarget`、`kcalTolerance`、`proteinMin`、`budgetUse`、`structure`、`hardRules`、`boxStyle`（3 个命名模板，用 `{main}` 占位）、`reasons`（3 条）、`poems`（6 首，3-5 行）、`bless`（2 条语音祝福）、`closing`（1 句收尾）。
2. 重新生成本手册：`node engine/cli.js export-refs`。
3. 跑一遍自检：`npm test`（必须 0 失败；新情绪要能在默认约束下产出 3 盒）。
4. 在 `references/receipt-poems.md` 里确认新诗词已生成，并按下面的写作守则检查语气。

## 五、语气与安全守则（改内容时必须遵守）

- 不评价体型、不鼓吹节食、不承诺减重效果；「减脂」的落点是**把热量算清楚再吃**，不是少吃。
- 不出现烟酒、赌博、迷信、拜金元素；盲盒是**替用户做决定**，不是碰运气，不要写成抽奖。
- 不与其他品牌做对比，不贬低麦当劳的产品与形象。
- 不输出医疗、营养或治疗建议；热量与营养为估算值，一律以麦当劳官方渠道实时结果为准。
- 不诱导浪费：份数按人数匹配，预算不足时优先减配餐与甜品，并如实写明。
- 小票诗避免说教句式（必须/应该/加油/一切都会好），以「陪伴 + 具体」为基调。
